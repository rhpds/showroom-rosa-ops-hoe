== Introduction

OpenShift Service Mesh 3 deploys Istio through two custom resources:

* `Istio` — control plane (`istiod`) in a project such as `istio-system`
* `IstioCNI` — CNI DaemonSet in a separate project such as `istio-cni`

The Operator does *not* create ingress/egress gateways for you.
Gateways are application-layer resources you deploy later (gateway injection + OpenShift Route in this workshop).

Official reference: https://docs.redhat.com/en/documentation/red_hat_openshift_service_mesh/3.3/html/installing/ossm-installing-service-mesh[Installing OpenShift Service Mesh].

:numbered:
== Deploy the Istio control plane and CNI

. Create the control-plane project (skip if it already exists):
+
[source,sh,role=execute]
----
oc new-project istio-system
----

. Create the CNI project:
+
[source,sh,role=execute]
----
oc new-project istio-cni
----

. Label the control-plane namespace so it matches the discovery selector used below:
+
[source,sh,role=execute]
----
oc label namespace istio-system istio-discovery=enabled --overwrite
----

. Create the `Istio` and `IstioCNI` resources.
Discovery selectors limit which namespaces the control plane configures — only namespaces labeled `istio-discovery=enabled` are included.
+
[source,sh,role=execute]
----
cat <<'EOF' | oc apply -f -
apiVersion: sailoperator.io/v1
kind: Istio
metadata:
  name: default
spec:
  namespace: istio-system
  values:
    meshConfig:
      discoverySelectors:
        - matchLabels:
            istio-discovery: enabled
---
apiVersion: sailoperator.io/v1
kind: IstioCNI
metadata:
  name: default
spec:
  namespace: istio-cni
EOF
----
+
.Sample Output
[source,text,options=nowrap]
----
istio.sailoperator.io/default created
istiocni.sailoperator.io/default created
----
+
[NOTE]
====
If your cluster nodes run RHEL / RHCOS *10*, set `spec.values.global.nativeNftables: true` on both the `Istio` and `IstioCNI` resources per the product docs.
This ROSA workshop path was validated on RHCOS 9.x without that field.
====

. Watch the control plane and CNI until both report `Healthy`:
+
[source,sh,role=execute]
----
oc get istio default
oc get istiocni default
oc get pods -n istio-system
oc get pods -n istio-cni
----
+
.Sample Output
[source,text,options=nowrap]
----
NAME      REVISIONS   READY   IN USE   ACTIVE REVISION   STATUS    VERSION    AGE
default   1           1       0        default           Healthy   v1.28.10   30s

NAME      READY   STATUS    VERSION    AGE
default   True    Healthy   v1.28.10   30s

NAME                    READY   STATUS    RESTARTS   AGE
istiod-xxxxxxxx-xxxxx   1/1     Running   0          20s

NAME                   READY   STATUS    RESTARTS   AGE
istio-cni-node-xxxxx   1/1     Running   0          20s
istio-cni-node-yyyyy   1/1     Running   0          20s
----
+
Exact Istio patch versions vary by Operator channel (`stable` currently installs Service Mesh 3.3.x). Proceed when `STATUS` / `state` is `Healthy` and `istiod` is `Running`.

. Optional: watch until ready:
+
[source,sh,role=execute]
----
oc wait --for=jsonpath='{.status.state}'=Healthy istio/default --timeout=300s
oc wait --for=jsonpath='{.status.state}'=Healthy istiocni/default --timeout=300s
----

*Congratulations!*

The Service Mesh 3 control plane and CNI are deployed. Next you enroll the Bookinfo application in the mesh.
